# Handoff: wave RV10, administration changes need a signed-in session (16 November 2026)

## State

- **Built:** spec 085. The router makes every route below `/api/v1/admin/` that is not a `GET` or `HEAD` session-only when it is registered (`withAdministrationRule` in `internal/httpapi/router.go`). A token with the `admin` scope still reads Administration. The report is `docs/reports/2026-11-16-wave-rv10.md`; the decision is ADR-052.
- **Migrations:** none.
- **Upgrade:** nothing to do. A script that changed Administration with a token gets `403 session_only` and must make that change in the browser.

## For whoever lands this

- `docs/api/routes.txt` and `openapi.json` change on 13 lines. If another wave adds routes below `/api/v1/admin/`, regenerate both after merging (`UPDATE_ROUTES=1 go test ./internal/app/ -run 'RouteTable|APIDescription'`): a new change there shows as `session-only` by itself.
- `TestEveryAdministrationChangeNeedsASession` walks every route; a wave that meant a token to change Administration must change the rule in the router and ADR-052, not the test.
- The design picture `tokens` changes with the label and help text of the scope.
