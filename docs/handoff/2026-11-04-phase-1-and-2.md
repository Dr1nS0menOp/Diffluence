## Bugs that only real runs found

The tests were green for all of these. Each is fixed and now has a test.
1. **Nobody created through SCIM could log in.** Authentik does not mark addresses as verified, which my imitation of it assumed. Accounts now link on the id that SCIM and OIDC share (ADR-020).
2. **The Docker installation did not start:** the data folder belonged to root.
3. **The backup could not be read back:** `master.key` was copied as root.
4. **An office behind one address would be locked out at nine o'clock:** successful logins counted towards the limit per address.
5. **A group claim could block a login:** the "last administrator" guard also fired on provider syncs.

- Restoring from the trash is for space admins only, so someone who deletes their own page by mistake must ask. Tell me if that is too strict.

## How to test (plain language)

Start it from WSL in the repo folder:

```sh
sh scripts/setup-secrets.sh && docker compose up -d --build
printf '%s\n' 'een lang wachtwoord' | docker compose exec -T diffluence diffluence user create-admin --email jij@example.com --name "Jij"
```

Open http://localhost:8080 and log in.

**Writing**
- [ ] Create a space. You land on its home page.
- [ ] New page: type `# Kop`, then `**vet**`, then `- lijst`, then ` ``` `. They turn into formatting as you type.
- [ ] Add a table and an image. Publish.
- [ ] Edit again, type something, wait for "Draft saved", close the tab, reopen: your text is back.
- [ ] Publish, open History, tick two versions, Compare. Restore the old one.
- [ ] Drag a page onto another page in the sidebar. The address stays the same.

**Permissions** (use a second browser or private window)
- [ ] Administration, Users: make a member and a guest.
- [ ] Space settings: give the guest the Viewer role.
- [ ] On a page: Restrictions, add yourself under "view". Add a page below it.
- [ ] As the guest: the page is not in the tree, not in search, and its address says it does not exist. The page below it neither.
- [ ] Back as yourself: Restrictions, "Why can or can't they?", pick the guest. It names the restriction.
- [ ] Without a grant, you as administrator cannot read other people's spaces. Administration, Spaces, Recover access gets you in, and the audit log shows it.

**Accounts**
- [ ] Your account: set up an authenticator app. Save the recovery codes. Log in again: a code is asked.
- [ ] Add a passkey and log in with it.
- [ ] Disable a user while they are logged in: their next click logs them out.

**Safety net**
- [ ] Delete a page. Space settings, Trash: restore it.
- [ ] Administration, Audit log: everything you did is there. Press Verify the chain.
- [ ] `bash scripts/restore-drill.sh`: it ends with "restore drill passed".
- [ ] Connect your own Authentik with `docs/operations/identity-providers.md`.

Stop it with `docker compose down`. Add `-v` only if you want to throw the data away.
