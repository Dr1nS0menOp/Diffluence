# Handoff: wave O3, backups that run and restore (2026-11-11)

Spec 054, ADR-042. Branch `wave-o3` from main `bd2d920`. No migration.

## What changed

- `compose.yaml` has a `backup` service, on by default, built from the `backup` stage of the `Dockerfile` (`postgres:16`, `gnupg`, the `diffluence` binary). Its script is `deploy/backup/backup-service.sh` (`loop`, `once`).
- `scripts/setup-secrets.sh` makes `backup-key/backup.key` and `./backups`. Both are in `.gitignore` and `.dockerignore`.
- `app.New` returns `*app.UpgradeRefused` with kinds when the checks before an upgrade refuse. `diffluence serve` then waits (`app.WaitWhileRefused`), serving `/livez` 200, `/readyz` 503, the API 503 and a public page with kinds and commands only, and tries again every minute or on SIGHUP.
- The first upgrade with no backup ever and no earlier waiver goes on, recording `system.upgrade_without_backup` (`first_upgrade_under_the_backup_rule`).
- `diffluence migrate` runs the backup check (`app.CheckBackupBeforeMigrating`) and writes the upgrade marker; `--without-backup` records `operator_override`.
- `scripts/backup.sh` sends SIGHUP to an unhealthy node after noting a backup.
- `scripts/restore-check.sh` is the weekly restore of a real installation.
- The restore drill backs up while the node is down, runs the service once (and without a key), restores the service's backup, and runs the restore check.
- CI builds the `backup` image in the container job.

## For whoever lands this

- **Wave AC (spec 052, ADR-041) writes audit events to `audit_pending` and has `audit.RecordSealed` for writes made before migrating**, because the previous release's schema has no `audit_pending`. Three writes in `internal/app/upgrade.go` happen before migrating and must use `RecordSealed` after the merge: `markUpgrade` and `NoteBackup`, which AC changes in its own branch, and `recordWaiver`, which is new here. `readBackupFacts` and `lastBackup` read `audit_events`; once AC lands, a note still waiting to be sealed is missed for up to a second, so read through AC's view if it offers one.
- ADR-042 is written after ADR-040; ADR-041 arrives with AC.
- The mutation list changed four existing lines of wave O7 and FU (the backup check moved into `backupProblem`, the marker into a function) and adds fourteen.

## Test images never take the name of a real installation

On 2026-11-11 a run of the restore drill built `diffluence:local` from a builder's worktree. That is the image name a real installation on the same Docker daemon runs, and that installation then started the wrong build and refused its migrations. Nothing was migrated. Now:

- the drill tags its own images, `diffluence:drill-<pid>` and `diffluence-backup:drill-<pid>`, through `DIFFLUENCE_IMAGE` and `DIFFLUENCE_BACKUP_IMAGE`, and removes them at the end;
- `restore-check.sh` takes the image the live container runs, and never builds or tags one;
- `restore.sh` never builds when the image exists;
- the upgrade test uses binaries, not Compose.

Any new script that runs `compose.yaml` must set its own project name and both image names.
