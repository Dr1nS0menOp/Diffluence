# Handoff 2026-11-05: wave C, working together

## What was decided

- The product owner has no mail server and asked for an open-source one. Mailpit is an optional service for testing (spec 010, D26). Production takes any SMTP server.
- A notification is a row per person and event, made from the outbox. Access is checked three times: when the row is made, when it is shown, and when a mail is written.
- A comment holds a quote, not a position, so the words stay marked while a page changes, and a thread never points at the wrong sentence.

## What was done

- Spec 010 holds the study, 26 decisions and the plan.
- Migration 0007 adds comments, reactions, mentions, tasks, watches, notifications, the mail queue, requests for access and follows.
- New packages: `comments`, `tasks`, `watches`, `notify`, `mail`, `sharing` and `feed`.
- Comments under a page and on chosen words or images, with a panel beside the page.
- Reactions, mentions, tasks with a person and a date, and Your tasks.
- Share, asking for access, and asking to edit.
- Watching pages, branches and spaces, and Publish without notifying.
- The bell, the notifications screen and notification settings.
- Mail through SMTP with required STARTTLS, at once or as a digest, with one-click stop.
- The start screen with For you, Recent activity and Popular, and following people.

## Found and fixed by the tests and pictures

- An empty comment box handed an empty string to the editor, which goes through an HTML parser. The Content Security Policy refused that, so every comment box broke. The box now starts from an empty document object.
- The first test of a forged unsubscribe token only changed a sealed token. It now also sends a token made by hand.
- Moving between tabs did not move the focus. One `Tabs` component now does this, for the start screen, the panel and Your tasks.

## Closed after blueprint 05

Blueprint 05 found five problems in this wave. All have a test and a mutation line.

- GAP-004: a mention stores the id only. Reading, export and mail fill in the name, and search takes it from `page_mentions`.
- GAP-006: publishing opens a thread only when its quote is in the published text.
- GAP-007: allowing lists each level and what it opens, and is refused for someone who cannot manage them all. Allowing now also opens restrictions when the space was the first thing in the way.
- GAP-021: reactions stop in an archived space. Archived pages do not exist until wave D, so `reaction.set` must join that rule in `Evaluate` at the merge.
- GAP-030: following needs *view profiles*, and answers the same for a person who does not exist.

## Closed after blueprint 06

- SEC-265: recent searches and the state of the tree are kept per person, and logging out removes them. What older versions kept without a person goes when the app starts.
- SEC-266: comment drafts are kept per person, go at logout, and stay seven days at most.
- SEC-416: three tests with a fake server show that a wrong certificate gets nothing, also with implicit TLS.
- SEC-422: the request log writes the route instead of a token, also for `/hooks/`, which wave H adds.
- SEC-407: `comments.BlankQuotes` takes the words of a removed version out of quotes. Nothing calls it yet, because versions can only be removed from wave D on. Wave D must call it there.

`scripts/mutation-check.sh` can now break frontend code as well, with `mutate_web`.

## A mistake along the way

Scripts for this wave once wrote into the main repository instead of the worktree, because `[IO.File]` ignores `Set-Location`. Those changes were moved to the worktree and removed from the main repository before anything was committed.

## Unfinished, or seen along the way

- The status lines in chapters 1, 2, 3, 7 and 10 say what is still open.
- Give access in the Share dialog (COL-043) is not there. The dialog leads to the lock in one step.

- An administrator cannot set notification defaults for new users (COL-078).
- A note with an answer to a request exists in the API, but has no field on screen.
- Someone without *edit* sees a task checkbox that cannot be ticked. In Your tasks the reason only shows after trying.
- Blog posts do not exist yet, so requirements that name them count pages only.
- A request that a browser drops halfway, such as a poll of the bell during a page change, is logged as an error. That is older than this wave, and only the log is affected.
- The feed, the fan-out to many watchers and searching by a mentioned name get their measurement under load in phase 3.
