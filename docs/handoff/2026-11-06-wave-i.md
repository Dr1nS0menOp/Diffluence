# Handoff: wave I, databases, and PDF in the browser

Date: 2026-11-06. Branch: `wave-i`. Spec: `docs/specs/019-databases-wave-i.md`.

## What is built

PdfCraft and GridCraft in a sandboxed frame, served from `/vendor/` with a policy of their own. A database as the page kind `database`, with our own grid: keys of a spreadsheet, formulas, six column types, sort, filter, paste from Excel, CSV in and out, and an example in the example space. The status lines in `docs/blueprint/03-functional/13-other-content-types.md` say what is still open.

2. **CSV guard.** Wave H guards every CSV the server writes. A database is exported in the browser, so `csvField` in `web/src/components/sheet/csv.ts` is the rule for that side. Editing together does not apply to a database: it stays on private drafts.

## For the product owner

1. **Wave E was wrong about PdfCraft.** Both builds are MIT or Apache-2.0, by their own licence files.
2. **Size.** PdfCraft is 18.7 MiB stored and sent, and 52.6 MiB unpacked in the browser of someone who opens a PDF. It counts as under the 30 MB line for that reason: say so if you see it differently. The program grows by about 28 MiB.
3. **GridCraft is not the core.** It paints on a canvas and gives nothing back, so search, history and permissions could not work, and a screen reader gets nothing. Open in GridCraft is the way to heavy work: changes come back only as a download.
4. **A screen reader cannot use either viewer.** Download always stays beside PdfCraft.
5. **Both builds are alpha.** The way a file gets in is by dropping it on the canvas, which neither project promises. A new version needs a look.

## Not built

Cards, board and saved views, a view in a page, an entry as a page, and person, tag and page columns. Selecting a block of cells to copy. A PDF inside the page itself: it opens in a window over the page. An HTML, PDF or public-site copy of a database shows a formula as written, because formulas are worked out in the browser.
