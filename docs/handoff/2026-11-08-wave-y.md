# Handoff 2026-11-08: wave Y, replacing the master key

Branch `wave-y`. Spec 034, report `docs/reports/2026-11-08-wave-y.md`.

## Done

`master.key` can be replaced without downtime: `diffluence key add`, `promote`, `reseal`, `check`, `retire`. Every sealed value names its key. Backups and restores carry a key on its way in or out, and a restore ends with `key check`. The restore drill replaces the key halfway through a backup. The encryption job resumes where it stopped.

## For the product owner

Nothing to decide now. Worth knowing:

- Replacing `master.key` keeps the root that signs audit checkpoints. If the key file itself was stolen, replacing it stops the thief from reading what is sealed after the change, but not from forging checkpoints. Replacing the root is left (SEC-714).
- After `key retire`, unsubscribe links in mails sent before the change stop working.
- Backups from before a change need the old key: keep them until the change is done.
