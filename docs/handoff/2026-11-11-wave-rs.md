# Handoff: wave RS, restoring over the live installation from the console

Spec 059, report `docs/reports/2026-11-11-wave-rs.md`.

## Where things are

- `internal/restore`: the state of a restore (`restore.go`) and the worker's steps in order (`run.go`). The real steps are in `cmd/diffluence/restore.go` (`shellSteps`: gpg, pg_restore, psql, tar).
- `internal/app/restoring.go`: what a node does: the watcher in `Serve`, the waiting page, and `WaitWhileRestoring`, which `cmd/diffluence/main.go` calls before every start.
- `deploy/backup/backup-service.sh`: `restore` (prepare, safety backup, run) and `way-back`.
- Migration `0049_restore_from_the_console.sql`: the schema `ops` and `sessions.reauth_method`.

## For whoever lands this

- **Migration 0049.** Wave O2's rewrite check applies; every index is on a table the same file creates, and the one `ALTER TABLE` adds a nullable column without a default.
- **`compose.yaml` changes the backup service.** The data volume is no longer read-only, and it gets `DIFFLUENCE_MIGRATE_DATABASE_URL_FILE`, `DIFFLUENCE_DATA_DIR` and `DIFFLUENCE_INSTANCE_NAME`. An installation updates `compose.yaml` with the release; the changelog says so.
- **`scripts/e2e`** reports one complete backup after making the admin, so the console offers a restore. No design picture shows the backup page, so no picture changed.
- **`GrantApp`** now also grants the application role `USAGE` on `ops`, and the right to read and write its tables.

## Rules for later work

- Anything that must survive a restore goes in the schema `ops`, never in `public`, and has no foreign key into `public`.
- Every backup command leaves out the rows of `ops` (`--exclude-table-data='ops.*'`).
- A test that runs Compose uses its own project name and image tags; never `diffluence:local`.
