# Handoff: wave O5, releases (2026-11-11)

Spec 057. What is built, how it is proven and what is open is in `docs/reports/2026-11-11-wave-o5.md`.

## For whoever lands this

- **Wave O3** adds a `backup` stage to `Dockerfile` on `postgres:16`. This wave only changes the three existing `FROM` lines, adding a digest, so the merge touches different lines. The backup stage's image can get its digest in the same way, or from Renovate.
- **`.github/workflows/ci.yml`** gains one job, `release-dry-run`. It runs only on pushes to `main` and at night, never on pull requests.
- **`.github/workflows/release.yml`** is new. It runs only on a pushed tag `vX.Y.Z` on `main`. No tag was made or pushed in this wave.
- **No migration, no Go or npm dependency.** The release tools are listed in `docs/dependencies.md` under "Release tools".

## For the first release

- **Before you push the tag:** move the `Unreleased` part of `CHANGELOG.md` under `## X.Y.Z`. The workflow refuses a tag without its section.
- **During the run:** watch the first run of `release.yml` from start to end. Signing, provenance, the image push and the draft release have never run. Each step's name says what it proves.
- **After the run:** verify by hand as `docs/operations/release.md` step 8 says, then publish the draft.
- **Image visibility:** the image goes to `ghcr.io/<owner>/diffluence`. A new package on GHCR is private by default, so make it public in the package settings after the first release.

## Not done here

- An `apt` or `dnf` repository (spec 048 D6: later).
- Digests for the images in `compose.yaml`, the backup stage and `Dockerfile.dev`.
- Feature toggles: the rule is written, but no feature ships dark (OPS-097).
