# Handoff 2026-11-06: wave N, the rest of files

Branch `wave-n`. See spec 024 for every decision.

## What is built

- **Uploads:** progress in percent and Cancel for files of 1 MiB and more (FIL-011). A drop of one file on a tile makes its next version, under the name of the tile (FIL-013). An archive stays one file (FIL-014).
- **List of a page:** who added a file, when, and whether the page shows it (FIL-036). A Clear up button for what nothing uses (FIL-017).
- **Preview:** on top of the page, from a tile and from the list, with Previous, Next and Download (FIL-027). Code has colours, from the highlighter of the code block (FIL-028).
- **Labels:** on files, by the rules of page labels (FIL-039, FIL-041, ORG-042). Search finds the page that holds a labelled file.
- **Links:** every version has its own address, and the details offer a link to the latest or to one version (FIL-042).
- **Files screen:** filters by type, label and person, and bulk delete for space administrators (FIL-043, FIL-045).
- **History:** the page history lists what happened to files (FIL-050).
- **Limit:** an administrator sets a limit per space under Spaces (FIL-020).
- **Tiles:** small or large, under the tools of a selected tile (FIL-026, partly).

## Fixed on the way

- **Old versions could not be downloaded.** FIL-037 was marked as built, but no route served one.
- **Renaming wiped the comment.** The comment was stored and never sent, so the form saved an empty one.

## For the product owner

- **Decision:** a preview image of the first page (FIL-026) needs a renderer on the server or the PDF viewer inside every tile. Is a new helper or that much weight worth it? Until then a large tile is a larger card without a picture.
- **Limit:** it does not stop a page copy, a page move or an import, because stopping those halfway is worse than going over. An administrator sees the total. A limit also leaves the trash out, like the total on the Files screen.
- **History of files** starts with this release. The audit log holds the past, but it is not for readers.

## Not proven

- **PDF and office files in the preview:** the preview hands them to the viewer, which earlier waves test. An office file needs Gotenberg, which only ran against a stand-in.
- **Two uploads taking the last room at once:** the row lock decides, and no test runs them in parallel.
- **Cancel on a real slow connection:** the test holds the request back. It proves the screen, not a half-sent body on a real server.
- **A large file whose name is taken:** the server answers before it has read the body. This already held for `fetch`, and it was not tried with a large file on `XMLHttpRequest`.

## Left

- File labels are not in bundles or template exports, and a copied file starts without labels.
- A video or sound block is not remapped when a page is copied: `document.AttachmentIDs` only knows images and files. Seen here, not changed. `FilesShown` knows all of them, so clearing up is not affected.
- `TestOneChangedByteStopsABundle` passed by luck under its mutation when the changed byte broke the JSON, so the mutation check failed now and then. It now also asks for the reason.
- The drop on a tile only runs in the editor. A reader who may add files has to open the editor first.
