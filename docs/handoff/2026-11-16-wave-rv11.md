# Handoff: wave RV11, settings changes record what changed (16 November 2026)

## State

- **Built:** spec 090. Every `settings.updated` event holds `changes`: each changed field before and after, or `{"redacted": true}` for a field not listed as safe (deny by default; the organisation name is redacted on purpose). Values are cut at 200 characters and addresses lose a user name and password. The public appearance answer comes from a copy per node of 30 seconds, dropped by every write of the settings service on that node, and is limited to 600 calls a minute per address without a login. A link mark keeps no title; terms and help addresses refuse a user name or password and keep plain http. The report is `docs/reports/2026-11-16-wave-rv11.md`.
- **Blueprint:** SEC-603 names spec 090; SEC-805 is built.
- **Migrations:** none.
- **Upgrade:** nothing to do.

## For whoever lands this

- `settings.Service.Write` takes a fourth argument, the `settings.SafeFields` whose values the audit row may keep. A new caller passes its list; `settings.SafeFields{settings.WholeValue}` for a value that is no object. Leaving a field out records it as changed without values.
- A new field of a section fails `TestEveryFieldOfEverySectionHasAnAuditDecision` until it is added to `sectionSafeFields` or `sectionRedactedFields` in `internal/settings/changes.go`.
- `settings.updated` of the console's general values and of the backup schedule no longer carries the values at the top level of its details; they are under `changes`.
- Fifteen mutations are new under "Spec 090, wave RV11".

RV11-1 to RV11-6 in the report were decided on your behalf and may be overruled: above all RV11-5 (a link keeps no title at all, rather than a capped one) and RV11-6 (plain http stays allowed for the terms and help addresses).
