# Handoff: wave F, people, access and administration

Date: 2026-11-05. Branch: `wave-f`. Spec: `docs/specs/013-people-and-admin-wave-f.md`.

## What is built

People and profiles, name cards and marks. Reset, invitation and sign-up by a link. New passwords of 15 characters, checked against a Bloom filter of about 5 million leaked passwords. The prompt for a stronger sign-in, the second-factor rule and the idle warning. Tokens, step-up by password, passkey or a fresh login at the identity provider. Personal spaces, Manager, who has access, a summary before someone loses access, a safe CSV. Restrictions in three states, group owners, dates per person, first use. The console: summary, warnings, settings search, user and audit filters in the address, bulk actions, CSV import, service accounts, rules, look, maintenance mode, jobs, reports, unused files, anonymising, `diffluence audit prune`.

The product owner's decisions are D21 to D25 in the spec. What was decided while building is D13 and D26 to D29, and "What differs from this plan" lists the rest.

## Things to know

- `perm_spaces` now lives in `0010_people.sql`, so the SQL mutation about guests points there.
- `settings.value` is `jsonb`: store JSON, also for a plain string.
- Everything that verifies the audit log goes through `audit.Check`. `audit.Verify` alone only sees the chain, which can be rewritten end to end.
- The console warning on the audit log reads the last `audit.verified` event of the worker, so pressing Verify cannot take it away.
- A step-up dialog answers for every request through `answerReauthWith` in `api.ts`, so no screen has to think of it. Polling goes through `api.poll`, which marks the request as background (D8).
- The filter needs a rebuild only when the list changes. The source file and its hash are in `docs/dependencies.md`.
