# Handoff: wave H, insight, automation, the platform and editing together

Date: 2026-11-06. Branch: `wave-h`. Spec: `docs/specs/015-platform-wave-h.md`. Decisions: ADR-026.

## What is built

Parts 1 to 5 of the spec. Analytics with counts and name mode, insights for page, space and instance, search terms, rules with test run, log, limits and templates, webhooks, one outward client, one CSV guard, an OpenAPI description, token scopes, `diffluence client`, presence, and editing together with the `collab` service. The status lines in `docs/blueprint/03-functional/` say what each requirement still misses.

## Choices made while the product owner slept

1. **Charts use the `Chart` component**, not HTML bars as D7 said. Wave E added it after the spec, the design standard now names it, and it brings the table with the numbers.
2. **`connect-src` stays `'self'`.** The socket goes through `/collab` on our own origin, so the `wss:` of the plan is not needed, and the policy stays narrower.
3. **Rules and webhooks sit in Space settings**, not in the sidebar, so the sidebar stays as approved.
4. **An outward address is one field in a rule,** on a host from the list, instead of a host and a path.
5. **Webhook secrets are shown once, and two signatures go out for a day after a rotation,** as the spec says. An instance rule without a page cannot notify its owner: notifications hang on a page, so its state shows on its own screen only.
6. **Offline text leaves at logout (SEC-265, SEC-266).** The shared document in the browser and page text that failed to save are keyed per person. The first goes at logout, and both stay only while they hold work nobody else has, for at most seven days.
7. **`token.used` fails closed.** A token whose use cannot be recorded is not used (SEC-807).

## For the product owner

1. **Name mode** stays off, and the setting names the risk. Have someone check before a customer turns it on.
2. **Removing a version does not reach the shared document.** Purging the page does.

## Not built

- **COL-096, 30 editors:** not measured. Two browsers are tested, and AC-E7 is open.
- **A live hostile client:** the gate on stored state is tested through its route, and each browser's schema drops what it does not know. No test connects a hostile client to the running service.
- An upgrade of the service while people type, and a block move with a colleague typing, from the test list of part 5.
- More than one service node, which phase 3 must settle.
- The rule form offers five kinds of condition in one group. Nested groups and the other kinds work through the API and through import. The form lacks copy target, move, restrict, owner and new page from a template in the same way.
- Choosing a service account as the account of a rule works through the API, not in the form.
- CSV of archived items (PLT-019), and the most active people of PLT-016 in counts mode.
- OAuth stays in phase 7, as ADR-026 says.

## How to run editing together

`E2E_COLLAB=1 scripts/e2e collab.spec.ts`. Without that setting, those tests skip themselves, and every other test runs with private drafts. To install it, see `docs/operations/install.md`.

## The mutation check

From the Windows mount it needs about five minutes per line, so a full run takes many hours. Copied to the container's own disk, all lines ran in under two hours. Four old lines had gone stale through this wave and were repaired. A rule's message was caught by a second check in `notify`, so its mutation needed a new test: a person who can see the found page, but not the page the run started from.
