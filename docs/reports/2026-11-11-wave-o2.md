# Report: wave O2, upgrades made stronger

Date: 2026-11-11. Spec 053, the second wave of spec 048. Lines OPS-070 to OPS-076, and OPS-043.

## What was built

- **Contract migrations wait a day.** `DIFFLUENCE_CONTRACT_GRACE`, 24 hours by default (spec 048 D1), instead of a fixed 10 minutes. Zero is allowed for a test installation, a negative value is refused at start. The health check and the shipped alert warn a day after the grace, not a day in all, so a normal upgrade does not raise them.
- **A time limit on every migration.** `statement_timeout` of a minute, or what the header `-- statement_timeout:` gives. A migration that runs longer stops and rolls back, and nothing of it stays.
- **Migrations outside a transaction.** `-- transaction: none` runs a file of exactly one statement on its own, with the lock, `lock_timeout`, `statement_timeout` and retries of the others. Afterwards it checks for invalid indexes and stops naming them, because a failed concurrent build leaves one, which `IF NOT EXISTS` would otherwise skip quietly.
- **The rewrite check.** `db.Lint` and `TestNoMigrationRewritesATable` refuse, from migration 0048 on, statements that rewrite a table or read all of it under its lock, on a table the same file did not create. An exception is `-- rewrite-ok: <reason>` in or right above the statement, and only for that statement.
- **Jobs across versions.** A worker claims only kinds it has a handler for. Before, an older worker could take a job of a kind only a newer release knows and mark it failed.
- **Events across versions.** A test sends every listener an event of an unknown type; all let it pass. Nothing needed to change.
- **Settings across versions.** Saving a section keeps the fields this release does not know. Before, saving on an older node erased what a newer one stored in the same section.
- **The upgrade test writes.** On the old release: a space, a published page, a draft, a comment and a file. The new release reads them and writes its own; the old one reads those while both run, and both sets again after the rollback. At the end the outbox must be empty, and no job may have failed and no event been set aside. The two nodes now share their file store, as nodes of one installation do; each keeps its own queue folder.
- **The version-skew policy**, `docs/operations/version-skew.md`: per part, how many releases may differ, for how long, and which test proves it. The release rule D2 (a contract migration only removes what the previous release stopped using) is in `migrate.go` and the release checklist; the six-month jump D3 is in the policy and `upgrade.md`.

## Found on the way

Two real faults across versions, both shown by a failing test first: the job claim and the settings save above. Neither is a security weakness; both could lose work during a rolling upgrade.

One existing test, `TestMaintenanceHoldsQueuedJobs`, queued a job of a made-up kind and counted on a worker taking it. It now registers its own kind, as the other job tests do. `TestContractMigrationsWaitForOlderNodes` let its nodes start an hour ago; with a grace of a day that alone held the migration back, so the mutation "contract migrations ignore older nodes" went unseen. The nodes now start days ago, so only the older node holds it back.

## Decided

- **One minute** for `statement_timeout`. Every migration of today runs in a fraction of that on the stress test's data; a longer one should be a background job (OPS-035), or say why in its header.
- **The rewrite check starts at 0048.** Migrations 0044 to 0047 are not released yet, but they ran in CI and on test installations; checking them would only rename what is already applied. From 0048 on, every migration is checked.
- **The check is a Go test, not a separate tool.** It runs in `make check` and in CI with the other tests, and needs nothing new.
- **Settings keep unknown fields by their JSON names.** A field this release knows but leaves out on purpose (`omitempty`) is not brought back; only names it does not know at all are kept.
- **A negative grace is refused, zero is allowed.** Zero is useful on a test installation; a negative number can only be a mistake.

## Not proven

- The editing service across two releases (OPS-070 stays partly).
- A migration that really runs for minutes on a large table, and `CREATE INDEX CONCURRENTLY` under load: wave 7, on the test server.
- The six-month jump: there is no release that old before 1.0 (OPS-076).
- The upgrade test in GitHub's CI with these writes: it ran in the dev container; CI runs it after a push.
