# Report: wave RV2, pinned and scanned builds, a walk of every route that takes an id, and a ticket for editing together (13 November 2026)

## What happened

Wave RV2 builds spec 067. It has three parts:

- the build gates;
- a test that walks every route taking an id as a stranger;
- a signed ticket that replaces the cookie between the API and the service for editing together.

## What was built

- **Builds.**
  - Every action in `ci.yml` and `release.yml` is pinned by commit SHA, with the version in a comment, and the jobs share one set of versions.
  - `postgres:16` and `node:22-slim` are pinned by digest.
  - CI builds the app, backup and `collab` images and scans each with Trivy. It runs `npm audit` for `collab`.
  - A release pushes, signs and attests all three images.
  - The `collab` image is built in two stages and ships without npm and corepack.
  - The backup stage takes Debian's security updates when built, and drops `gosu`, which only the postgres entrypoint used.
- **The walk.** `internal/app/route_walk_test.go` has two parts:
  - one table of the 47 routes that name an object while their rule is not an object rule, each with who it lets through;
  - a test that walks all of them as a stranger.
- **The ticket.**
  - **At the socket**, the API checks the session and the right to edit the page named in `/collab?page=`. It takes `Cookie` and `Authorization` off and adds a ticket signed with a key derived from the key file.
  - **At each check**, the service asks with that ticket. The API reads the session by id without counting it as activity, and answers with a new ticket.
  - **In the service**, this part lives in `collab/access.mjs`.

## Proof

| Part | Proof |
| --- | --- |
| Builds | actionlint in a throw-away container: no finding on the changed lines. `renovate-config-validator` accepts `renovate.json`. All three images build locally under check tags. Trivy, with the settings of CI, finds nothing HIGH or CRITICAL with a fix in any of them. Before this wave's changes, the scans found ten findings in `collab`, all in npm's own packages. The backup image had findings in `gosu` and in zlib, which has a Debian fix. The `collab` image starts and answers `/livez`. The backup image runs `pg_dump`, `gpg` and `diffluence` |
| Walk | `TestEveryRouteThatTakesAnIDIsProtected`; two mutations that remove an owner check behind a declared route, both caught |
| Ticket | Nine API tests, written first and seen failing. Six unit tests of the ticket. Eight tests of `access.mjs`. An e2e test through the real service. Mutations of every check |

## What the walk found

- No route gave a stranger data.
- `POST /api/v1/pages/bulk-move` answers 200 to a stranger. It reports `moved: 0` and "Not found." for each page, and the owner's page stays where it was. It is declared open.

## The mutation check

**Decided on the product owner's behalf on 2026-11-13:** the targeted list leaves out the internal/app wiring and tests; the nightly full run covers them.

The list holds:

- the changed files of `collab`, `internal/collab`, `internal/httpapi/handlers_collab.go`, `internal/identity/identity.go` and `together.tsx`;
- `internal/exchange/export.go` and `internal/savedblocks/savedblocks.go`, so that the walk's two mutations are selected too.

## Not proven here

- The CI and release workflows themselves, which run only on GitHub.
- The check that refuses a session still waiting for its second factor has no test of its own: the path needs a policy that forces a second factor.
- The check that a ticket's person still owns its session has no test of its own: a ticket with another person fails on its signature first.
