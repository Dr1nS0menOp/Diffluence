# Wave T: word forms, file names, and two checks from the self-test

Report of the build of spec 029.

## What was done

- Word forms: `internal/search/forms.go`. Each plain word becomes an OR of its forms in the tsquery; quoted words, fields and numbers do not.
- File names: the Files screen (`internal/attachments/versions.go`) now uses the same word index as the search box, through `search.Prefixes`.
- Install guide: a section on database size.
- Login limit: a test, `TestOwnGoodLoginsDoNotBuyGuessesOnOtherAccounts`. Before any change it showed 50 wrong passwords checked from one address with good logins in between, which is the plain limit of 50. So a good login does not buy extra guesses. The test and a mutation (a good login giving back two attempts) keep it that way.

## Tests

- `TestSearchFindsWordFormsAndKeepsTheExactTitleFirst` failed on the old search code and passes on the new one. It was run against the old code by copying the old files in, because git cannot read this worktree from WSL.
- The Files screen test failed in principle on the old match (`port` was found inside `report`); it was not run against the old code.
- Four new mutations, all caught when run on their own: a good login giving back more than its own attempt, a word asking for no other forms, quotes asking for other forms, the Files screen ignoring the name.

## Measurement

PostgreSQL alone at 1.5 CPUs, 50,000 synthetic documents of 120 words, GIN index. A word in every document as a prefix: about 10 ms with and without forms. A rare word: under 0.4 ms. Two words, newest ten: 0.3 ms as typed, 0.6 ms with forms. The synthetic set had no hits for its rare word, so that row shows the cost of an empty answer. The full setup of spec 028 was not repeated: its tools were not in the repository.

## Not proven

- The application under the load model with word forms.
- How often the forms find a page people did not mean, such as `noten` for `not`.
