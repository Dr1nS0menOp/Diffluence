# Wave N2: a notice for a new version, and closed comments (spec 041)

## What was built

- `webui.Build()`: a short id of the frontend inside the binary, a hash of `index.html`. Unit test: no frontend gives an empty id, the same `index.html` keeps its id, a changed one gets a new id.
- `/api/v1/appearance` carries `build`. No new route, no new query.
- A note under the top bar when the id changes, with Reload. It takes no focus and is a status for screen readers. The tab also asks again when a person returns to it.
- `reloadWhenSaved`: Reload sends `diffluence:before-reload`, the editor saves its draft, and the tab reloads after the save or after 5 seconds.
- `comments.PageGate`: `comments` asks `pages` whether a page takes new comments, inside its own transaction. It reads no column of `pages` any more.

## What the tests showed

- The first browser test, before the save-first step, failed: a reload right after typing showed only the old text, and the new words were only reachable through "Put it back". With the step, the words are simply there after the reload. So the test proves the step.
- `TestClosingCommentsStopsNewOnesAtOnce` was written before the change and passed on the old code; it pins the behaviour that the change must keep. Two new mutations break the new path: pages saying never closed, and comments ignoring the answer.
- Pictures `new-version-light` (desktop) and `new-version-dark` (390 px) were looked at: one line on desktop, wrapping cleanly on a phone, readable in both themes.

## Gates

- `make check`: passes. The first run failed on Prettier formatting in three new files; Prettier fixed them.
- `scripts/e2e`: 437 passed, 6 skipped, exit 0. The first full run failed on the `new-version-light` picture. That picture had been made in a run of only the new test, so the people page under the note lacked the groups and profile that earlier design tests make. The failure stopped the 42 tests after it, and that stop made `admin-spaces-1150` differ too. The pictures were made again in a run of the whole design file, and the full suite then passed.
- Mutation check (`MUTATION_JOBS=2`): 401 caught, 0 missed, 0 broken; the log ends in "all mutations were caught". The first run had one BROKEN line, from the new mutation "comments ignore what pages says about closing": dropping `closed` left a variable unused, which does not compile. It now reads `closed && false`, and that mutation is caught.
- Load budget (ARC-238): the notice adds no request. It rides on the existing `/appearance` poll, which runs every 30 s with spread, plus one refetch when a tab becomes visible. The build id is computed once per process. The closed-comments check still does one query per new comment, as before.

## Not proven

- A real rebuild under an open tab; the test changes the answered id instead.
- A draft save that hangs past 5 seconds; the browser backup covers it as before.
- Collaborative editing: no draft of its own, so the reload does not wait for it.

## Mistakes along the way

- I tried to write a stray file in the root of `C:`; the write was refused, so nothing was created.
- `go test -run` with a pattern containing `|` broke when passed through `wsl`; the pattern now comes from a file.
