# Report: wave SC5, the settings of a space (spec 083)

## What was asked

Rebuild the settings of a space as blueprint 03 arranges them (ADR-045, ADR-050), per the steps of spec 083, on top of the frame of SC1 and the shared settings pieces of SC4. The rules of the product owner of 2026-11-17 applied: until 1.0 the API and the app may change radically, and every feature must be usable through the API, which the spec now shows per entry.

## Through the API

Spec 083, "Through the API", has a table of every entry with the routes that read and change it and the rule each enforces. No route was missing and none was added. A personal access token still only reads, as for the administration (SC4 D22).

## Decided on the product owner's behalf (may be overruled)

D20 to D34 in the spec. In short: the space menu offers Space settings for the same permissions as before (D20); screens of their own keep their headings (D21); an old id of a screen leads to its address (D22); someone with only screens lands on the first (D23); the last owner cannot be removed in the form, the server is unchanged (D24); Create page starts the page in the space (D25); administrators as initials (D26); the jump field looks like the administration's (D27); the fold keeps its fields in the form (D28); review and approval save with Save (D29); the automation switch only while automation is on (D30); room for UR1 after Permissions (D31); no repeated first headings (D32); People's tools and the tables wait (D33, D34).

## Gates

The build server was switched off during the wave, so the gates ran locally, after the rename to Kenwerk:

- Web checks (tsc, eslint, prettier, UI strings, design rules, vitest: 859 tests): green.
- The e2e files this wave touches (0-design, space-settings, access, organising, new-version, links-tables, walk, roles, feedback, reading, people, access-roles, frame): 356 passed and 3 failed on the first run. The fixes: a link whose label did not match its text; the scroll test now moves between two sections, which keep the list's place; the Details test no longer adds an owner through the directory field. On the rerun, 0-design and space-settings passed: 170 tests.
- `0-design.spec.ts` twice more without updates: 156 passed each time. The pictures now centre the current entry of the space sidebar once more before they are taken, because entries that arrive late could otherwise move it.
- Not run: the full e2e suite outside the files above, `make check` beyond its web part, and mutation. This wave changed no Go code and no server access rule, so no mutation line was added.

## Pictures that changed

New: the space-settings sidebar, scrolled, the jump field with a match and with none, Details (at rest, changed, look only), Statuses and approvals, Features, Layout, Archive the space (active and archived), Delete the space, Pages still to write (with rows and empty), Permissions, a short section in the column, and Content at full width.
