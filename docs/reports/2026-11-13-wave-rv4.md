# Report: wave RV4, limits of signing in, counted audit erasures and exports, and accounts from single sign-on (13 November 2026)

## What happened

Wave RV4 builds spec 071: nine small, self-contained changes to signing in, the audit log, permission counting, single sign-on, guest invitations and the editing service. Each started with a test, seen failing before the change, except where noted under "Proof".

## What was built

- **Limits of signing in.** An IPv6 address counts by its /64. The limiter forgets ended windows in the order they began. Requests that change something below `/api/v1/auth/` and the first setup have a class of their own in the order of work. A wait for a password hash ends with its request; `HashPassword` and `VerifyPassword` take a context.
- **Audit exports.** A CSV ends with `#complete`, `#limit-reached` or `#incomplete` and the number of events. It is read in pages of 5,000 by seq. The audit export and the export download move their write deadline. The check from the console has a query limit of ten minutes.
- **Counting at commit.** Migration 0057 replaces the statement triggers on `permission_generation` with deferred constraint triggers that count once per transaction, at its commit.
- **Setting up a second factor.** Such a session reaches an exact list of route patterns.
- **Erasures.** `audit.ErasePersonal` returns its count; anonymising records it as `personal_parts_erased`. The check counts `erased_parts` and `recorded_erasures`, and fails when more parts are gone than recorded. Migration 0057 counts the parts erased before into `audit_erasure_baseline`, read-only for the application role.
- **Forgot password and sign-up.** The work runs beside a fixed 400 ms answer, for up to 30 seconds, sixteen at once per node.
- **Single sign-on.** `DIFFLUENCE_OIDC_AUTO_CREATE` is off by default; a new account needs `email_verified: true` unless `DIFFLUENCE_OIDC_ALLOW_UNVERIFIED_EMAIL=true`. The refusal is audited as `email_not_verified`.
- **Guests.** `sharing.InviteGuest` makes the whole decision of `POST /api/v1/spaces/{id}/guests`.
- **Editing service.** `isTheAPI` compares SHA-256 digests with `timingSafeEqual`. The collab block of `compose.yaml` has a read-only root, `/tmp` in memory, no new privileges and no capabilities.

## Decided on the product owner's behalf on 2026-11-13, may be overruled

- **Single sign-on defaults.** Both switches start at the safe value. Installations that relied on accounts at the first login set them before upgrading; the upgrade guide, the identity provider guide, `.env.example` and the changelog say so. `scripts/idp-test` sets `DIFFLUENCE_OIDC_AUTO_CREATE=true`.
- **A string `"true"` in `email_verified`** counts as not verified.
- **The check from the console** gets a longer query limit, not a job of its own. A job with a file remains possible later.
- **A failed erasure count fails the check**, rather than only being reported, because the migration counts earlier erasures and so an upgrade does not fail by itself.
- **Exactly the row limit** of an export ends as `#limit-reached`, also when no more events matched.
- **The sign-in class** is a quarter of the pool at once, eight times that waiting, five seconds of patience; readiness does not count it.
- **The targeted mutation check** leaves out `internal/app` and `scripts/mutation-check.sh`, as the brief asked; mutations of other files that run the tests of `internal/app` are selected by their own file. Its list names one changed file in each folder that holds a new mutation. A list of every changed file selected 385 mutations, also every one of `internal/permissions` and `internal/db`, which a test file and a grant line touched; on a loaded machine that run would have taken most of a day. The nightly full run covers those folders.

## Not proven here

- That Authentik or another real provider sends `email_verified` as the tests assume; `scripts/idp-test` was not run.
- That migration 0057 counts the parts erased before on a copy of a real installation; the count was not tested on prepared data.
- The compose settings of the editing service: the image was not started read-only here.
- The write deadlines of the audit export and the export download: no test sends for longer than the server's write timeout.
- That work beside the answer of forgot password survives a node that stops: it ends with the process.
- How counting at commit behaves with a sync of people running on the server.
