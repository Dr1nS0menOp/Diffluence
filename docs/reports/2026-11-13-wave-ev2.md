# Report: wave EV2, the switch of events from NATS to PostgreSQL (13 November 2026)

## What happened

Wave EV2 builds release A, part 2, of spec 068 (section 7): the switch from NATS to the event log in PostgreSQL, the drain of what NATS still holds, the trace column, and the check that release B, which removes NATS, runs before it upgrades. NATS stays in the code; removing it is wave EV3, after the measurements on the stress server.

The spec had a worker switch by itself once every node ran release A. This release switches only on an operator's command (D24), because the gates on the stress server (G2, G3) come after this wave and the spec keeps release A on NATS until they pass.

## What was built

- **The switch.** `diffluence events switch postgres` runs one transaction under the events lock: it refuses, naming them, while a node with a newest migration below 0053 was seen in the last five minutes (D25); it creates the cursors of the four consumers at the head (D26); it sets the transport, moves `changed_at` and clears the drain. Relay batches before it went to NATS; every one after it goes to the log.
- **The undo.** `diffluence events switch nats`, at any time (D27). New events go to NATS again; a worker keeps running the consumers of the log while a cursor is behind an event of its lane or a retry waits, so nothing in the log is left behind.
- **The workers.** A worker looks every 5 seconds whether the consumers of the log are needed (D32). The NATS consumers keep running in every case.
- **The drain.** The periodic task `note-nats-drained` asks NATS, once a minute between the switch and the drain, how many messages its four durables have pending or unacknowledged (`queue.Waiting`; a retry that waits is unacknowledged). With none, no older node, and no switch while it asked, it sets `event_transport.nats_drained_at` (D28). An older node that shows up undoes it; switching to postgres again starts a new drain (D29).
- **The check of release B.** `events.NATSRemovalProblem` names what still needs NATS on a database of any earlier release (D30). `diffluence events status` prints it with the transport, the drain and older nodes.
- **The trace.** `outbox.Enqueue` stores the W3C traceparent of the request when tracing is on; the sequencer copies it; a consumer, also on a retry, works in a span inside it (D31).
- **Migration 0059** adds the two columns and may run twice (D33); 0058 holds the number of wave DC2.
- **Timing in the tests of EV1.** Waits that assumed a fast machine now wait on a condition or check bounds read from the database clock (spec 068, 7.5).
- **The upgrade test** (CI job `upgrade`, G4) switches while both releases run, writes through both, and fails unless every event of the log reaches all four consumers, NATS is noted drained and `events check` passes, before and after the rollback.
- **The module boundary** (wave RV5's test): the event tables already have the owner `internal/events`. The switch reads the node registry of `internal/app` twice more and the check of release B the outbox once more; both are listed with the reason, since `internal/app` imports `internal/events`.
- **Wording.** Spec 068 sections 7.1 to 7.6 and decisions D24 to D34, `upgrade.md`, the changelog, the usage text of the command.

## Not proven

- G2 and G3 (stress server, hard reset of the database machine) and G1's open question from B2 stay open; they are the measurement wave.
- G4 proves delivery after the switch by cursors and the drain, not by the webhook witness of L4. In CI, release N is main, which already has migration 0053; the case of a release N from before 0053 was run here once, not in CI.
- The likely cause of the one failed CI run after EV1 is the wake test's 200 ms sleep; 80 runs of its old body under load did not fail, so the cause is not proven.
- Release B's check is not yet part of the checks before an upgrade: that is EV3.
- `internal/app` under the race detector takes about 16.5 minutes on this machine, close to the 20-minute limit of `make test-race`, on main as on this branch. A slow runner may reach the limit without any test being wrong.
- Migration 0058 holds the number of wave DC2 and goes when DC2 lands.
