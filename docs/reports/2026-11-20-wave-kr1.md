# Wave KR1: the product is called Kenwerk

Builder report for spec 095. It covers what was looked at, changed and proven.

## What was looked at

- Every tracked file on main `21368c4`: the old name was on 4,123 lines of 866 files, in exactly three spellings (`diffluence`, `Diffluence`, `DIFFLUENCE`), and in 34 paths.
- The short form `dfl`, on 46 lines: the token prefixes `dfl_` and `dfl_scim_` (shown to people, so renamed), and test role names, temporary folders, drill project names and advisory lock keys (never shown, so kept; spec 095).
- Name-bound values that a test or a stored row could depend on: the audit label of a checkpoint key change, migration checksums, the backup folder pattern in migration 0049, the transaction settings `diffluence.release` and `diffluence.permissions_counted`, the password rule against the product word, the issuer of two-step sign-in, the session cookie, the OpenAPI title.
- The mark: a river splitting in two, drawn as lines, no letter.
- Every `Confluence` mention: 45 lines on main, all kept.

## What changed

- **The script.** One idempotent script outside the repository (spec 095 D1) moved the 34 paths with `git mv` (`cmd/kenwerk`, `deploy/helm/kenwerk`, `deploy/kenwerk.example.yaml`, `deploy/systemd/kenwerk.service`, the monitoring files in `deploy/monitoring` and `internal/monitoring`), rewrote 800 text files with a case-keeping substitution, renamed the token prefixes, and rewrote the two sentences about the mark. It leaves alone the records of spec 095 D9.
- **A missed spelling.** The first run of the script knew the prefix in double quotes and backticks, not in single quotes; the end-to-end run that took the pictures failed on the two tests that read a new token (`people.spec.ts`, `platform.spec.ts`). The script now knows `'dfl_'` too, and a search for every `dfl` left over found only the names spec 095 keeps.
- **Formatting.** gofmt changed one file, `internal/db/boundary_test.go`, whose import order moved with the new module path. Prettier changed nothing.
- **By hand.** Spec 095, a name note above each of the two working-name notes in the blueprint, this report, the handoff and the changelog entry.
- **Pictures.** Every design baseline was deleted and taken anew, then the whole suite ran again against the new pictures.

## How the tests prove it

No new test: a rename adds no behaviour. The existing tests already pin the renamed values (the cookie, the token prefix, the metrics names, the Compose services, the OTel service name, the PDF helper user, the backup folder pattern, the password rule), and every mutation of `scripts/mutation-check.sh` still has to find its text in the renamed files.
