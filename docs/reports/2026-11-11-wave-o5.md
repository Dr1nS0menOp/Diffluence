## The tools

## Only a tagged release can prove

- **Keyless signing:** the workflow gets a GitHub OIDC token, and Fulcio and Rekor accept it.
- **Attestations:** the provenance on the files and on the image.
- **The image:** the build for both architectures under QEMU, and the push to GHCR.
- **The draft release:** its notes and footer.
- **The first run of `release.yml`.**

No tag was made. The release checklist says to verify each signature by hand after the first run.

## Decided

- **D1:** one Dockerfile for CI and the release image.
- **D2:** one systemd unit, with the path changed for the package.
- **D3:** a package never starts the service on a first install, and restarts a running one on an upgrade.
- **D4:** a draft release that a person publishes.
- **D5:** the dry run only on `main` and at night.
- **D6:** no toggle code before a feature needs one.
- **D7:** the unit sets the data folder and address.
- **D8:** SBOMs are not compared for reproducibility.

The reasons are in spec 057.
