# Report: wave W, files at rest and open lines of blueprint 04

Spec 032 holds the decisions. This report holds what was measured, what went wrong on the way, and what is left.

## Built

| Line | Result |
|---|---|
| ARC-194, SEC-332, SEC-725 | Stored files are encrypted in chunks of 64 KiB with AES-256-GCM, each with its own key bound to its name; a job encrypts old files and then refuses plain ones |
| ARC-093, ARC-195, ARC-196 | Office PDFs are kept under `previews/` by content hash, made once, shared by copies, purged daily when unused |
| ARC-133 | The feed and notifications take `before_id` next to `before` |
| ARC-071 | `GET /api/v1/system/capabilities`; the frontend does not use it yet |
| ARC-027 | 14 tables written by more than one module, each recorded with its reason in spec 032 |

## Measured

- Storing and reading 8 MiB through the store, in the development container: 414 MB/s plain, 226 MB/s encrypted (`BenchmarkEncryptedRoundTrip`). One machine, through a Windows mount.
- Memory while encrypting or decrypting: one chunk of 64 KiB, whatever the file size.

## Tests and mutations

- `internal/storage`: a wrong key fails at open; a file cut at a chunk border and a changed byte never read; a file moved under another name does not open; a file too large leaves nothing; plain files are read until the job is done and refused after; sizes 0, 1 and around the chunk border round-trip; range reads.
- `internal/app`: an upload is not plain on disk and comes back whole, also as a range; the job encrypts an old plain file, then refuses a plain file swapped in; a PDF is made once per content and purged when unused; the cursor skips nothing that shares a time; capabilities say only true or false.
- Eight new mutations, for storing plain, serving plain after the job, the last-chunk mark, the binding to the name, the job never refusing, converting on every request, purging what is in use, and the cursor.

## What went wrong on the way

- File changes made with .NET and a relative path landed in the main checkout instead of the worktree, because .NET resolves them from the folder the process started in. Three files changed there. They were moved to the worktree with a patch, the main checkout was restored and checked clean, and every later change used an absolute path. A leftover `app.go.orig` from `patch` was removed.
- One mutation did not compile at first, because a variable became unused. It was rewritten and the whole check was run again.

## Gates

- `make check`: passed.
- `scripts/e2e`: 396 passed, 6 skipped, 1 failed: the design picture `ContentView: the table of a space`. This wave changes nothing below `web/`; the picture already differs on main `6d337bd`, where wave U added date fields to that screen and wave T landed after it. The filter row wraps differently. It is left for main.
- Mutation check: 330 caught, and the log ends in "all mutations were caught", with no MISSED or BROKEN lines.

## Not proven

- Encryption on object storage (S3 is not built), and on a store with millions of files: the job lists every file each run until it is done.
- Rotating `master.key`: not built.
- The frames of ARC-111 and the PDF round trip of ARC-099: not built, no browser test.
- Killing an API node while people work: needs real servers.
