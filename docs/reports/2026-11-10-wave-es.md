# Wave ES: floating bars, near matches for names, and the storage limit everywhere

Report of 10 November 2026. Spec 047, the third wave of ADR-038.

## What was built

**Floating bars (EDT-006 partly, EDT-080).** Selected words get a bar with bold, italic, link, inline code, text colour, highlight, headings 1 to 3, bulleted and numbered lists, and Comment where comments are open. A selected image gets a bar with its tools and Delete. The fixed row keeps every tool. TipTap's `BubbleMenu` shows and places the bars; the keys, names and placement rules are ours: Alt+F10 to reach the bar, arrows inside it that follow the reading direction, Escape back to the text, above the selection and below it on a touch screen, never over the sticky row, wrapping on a narrow screen.

**Near matches for titles and file names.** Migration 0043 creates `pg_trgm` and two trigram indexes. Titles that hold the typed text, then titles near the typed words, come after exact titles and word matches. In the quick box a near title comes before a word in the text; in a full search after it, as the product owner decided. The quick box and the Files screen find file names the same way, through one shared condition and order. The search syntax gets no near matches. The check before migrating refuses an installation without `pg_trgm`.

**The storage limit everywhere.** The count is each stored object of a space once, also in the trash until it is purged. Copies of pages and branches, pages from templates, saving a page as a template and moving pages to another space are now checked before anything is stored. A large copy in the background reports a page whose files do not fit. The copy and move dialogs say before the action when the files will not fit.

## The new dependency

`@tiptap/extension-bubble-menu` 3.32.2, MIT, approved by the product owner on 2026-11-10. It was already in the lock file as an optional dependency of `@tiptap/react` 3.32.2; it is now a direct dependency at that exact version, and the lock file only changed its listing. It uses `@floating-ui/dom` 1.8.0, `@floating-ui/core` 1.8.0 and `@floating-ui/utils` 0.2.12, all MIT. Its peers ask for exactly the version of `@tiptap/core` and `@tiptap/pm`, so all TipTap packages move together.

## Decided in the build

- **Typo threshold 0.4, from five letters.** Measured on 45 typos and 26 decoys: 42 found at 0.4, 37 at 0.5, and no decoy above 0.25. The set is in `internal/search/testdata/typos.txt`, and a test reads it. Below five letters a word that only starts with the same two letters already counts as near (`week` found `Welcome pack.pdf` in the browser tests), so typos wait for five letters; a name that holds the text is found from three.
- **Placement `absolute`.** A fixed bar landed beside the selection by the offset of an ancestor that makes its own containing block.
- **No figures in the dialogs.** They say only that the files will not fit, so a dialog never tells how much a space holds.
- **The heading tools show an icon and a number,** so what is seen is part of their name, which the accessibility check asks.

## Load

Measured in PostgreSQL 16 in the development container, on 50,000 titles and 52,000 file names: the indexes are 2.9 MB and 2.4 MB and are used for every new query. A title that holds the text takes 4 ms; a typo that matches nothing 0.08 ms; a typo of a word in a tenth of all titles 48 ms, because every near title is ranked. The full load model of spec 028 was not run. Details in `docs/operations/limits.md`.

## Gates

`make check` passed. `scripts/e2e`: 452 passed, 7 skipped. The full mutation check caught all 503 mutations; 21 are new, 16 on the server and 5 in the browser code.

## Not proven

- A real touch screen. The test browser starts with a fine pointer, so the placement below the selection is proven by a unit test.
- A real screen reader. Axe and keyboard tests pass.
- A managed PostgreSQL that refuses `pg_trgm`. The check is tested on its rule.
- The quick box at the load model of spec 028 with near matches. That waits for the stress server.
- The sticky row is measured when a bar is about to show. A page that scrolls while a bar shows, before the row sticks, may let the bar pass under the row until the selection changes.

- A click on a file tile at the very moment the editor opens could be lost once the bars were in: the test that clicked at once failed every time, and passes when it first lets the editor take the focus, as the other editor tests do. The cause was not found. No person clicks within those milliseconds, but it is named here in case it shows elsewhere.

## Seen outside this wave

At a window of 360 pixels the editing page is 384 pixels wide, so the page itself scrolls sideways. The bar stays inside the page and is never wider than the window.
