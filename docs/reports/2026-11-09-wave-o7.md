## What was built, worst risk first

1. **The upgrade test runs in CI (OPS-036).** The blueprint said "CI tests this", and CI did not. The job `upgrade` builds release N (the target branch of a pull request, or main before a push) and this build, and runs them side by side on one database with traffic. Any failed request fails the job. `scripts/upgrade-check.sh` does the building, from `git archive`, so it leaves the repository alone.
2. **A safe way back (OPS-040).** The upgrade test now rolls back: it starts the old release again on the migrated database, logs in and reads. And a release refuses to start on a database in which a newer release ran a contract migration, naming that migration, both in `db.Migrate` and at the start of a node that does not migrate.
3. **Checks before migrating (OPS-038).** PostgreSQL 16 or newer (also for `diffluence migrate`), 512 MiB free in the data folder, a queue that answers, and, when `DIFFLUENCE_UPGRADE_BACKUP_MAX_AGE` is set, a backup noted within that time. A failed check names every reason at once and migrates nothing. The checks run only when there is something to migrate.
4. **The marker before an upgrade (OPS-041).** `scripts/backup.sh` runs `diffluence backup note` once a backup is complete, which writes `system.backup_noted`. A node that migrates a database with data first writes `system.upgrade_started`, with the migrations before and after and the time of the last noted backup.
5. **Migration progress in `/metrics` (OPS-022):** `diffluence_schema_migration`, `diffluence_migrations_pending_expand`, `diffluence_migrations_pending_contract`.
6. **Documents:** `upgrade.md` matches the code, including that one Compose node restarts in seconds and zero downtime needs two nodes; `release.md` is the release checklist; `backup-restore.md`, `install.md`, the gate list in blueprint 09 and `CHANGELOG.md`.

No migration was needed; 0044 stays free. No dependency was added.

## Needs real servers

These stay open until a machine is available: Helm on a cluster (OPS-002, OPS-031), LXC on a real host (OPS-004), two or more nodes, a NATS cluster and Patroni (OPS-011 to OPS-013), the load test at size (OPS-015), zero downtime on real machines behind a real load balancer (OPS-033), pgBackRest (OPS-051), a weekly restore of a real installation with an alert (OPS-054), and the 4 hours for 100 GB (OPS-055).

## Not proven

- The CI job itself has not run yet: the branch is not pushed. The same script ran in the development container with the same inputs, but the runner's `psql` and ports are assumed to be as in the other jobs.
- The refusal after a contract migration was proven with Go tests, not with two real binaries: no contract migration exists yet.
- The free-space check was tested on its rule, not on a full disk.
