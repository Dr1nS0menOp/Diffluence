# Wave RV11: settings changes record what changed, the appearance answer, two addresses

Builder report for spec 090. It covers what was looked at, what was decided and why, what was built, and what stays open.

## 1. What a settings change records

**Writers looked at.** Every place that writes the `settings` table and records an audit event:

| Writer | Event | Now records |
|---|---|---|
| `settings.SetSection`, `SetSectionConfirmed` (and through them the first setup and the organisation name) | `settings.updated` | `section`, `confirmed`, `changes` |
| `settings.ResetLook` | `settings.updated` | `section`, `reset`, `changes` |
| `settings.Write`: export limits, experimental parts, features for all spaces, company home page, draft retention, default permission set | `settings.updated` | `key`, `changes` |
| `settings.Update`: the console's general values | `settings.updated` | `changes` (the new values used to sit at the top level) |
| `backups.setSchedule` | `settings.updated` | `section`, `confirmed`, `changes` (`interval_hours` and `keep` used to sit at the top level) |
| `settings.CancelRetentionLowering` | `settings.retention_lowering_cancelled` | unchanged: it already names the days it took back |
| `settings.SetLogOverride`, `EndLogOverride` | `settings.log_level_set`, `settings.log_level_ended` | unchanged: level, hours and node are the whole change |
| `settings.SetMaintenance` | `maintenance.changed` | unchanged: `on`; the message stays out |
| Logo and font | `settings.logo_changed`, `settings.font_changed` | unchanged |
| `analytics.SetSettings`, `automation.SetRunsPerHour`, `publishing` self-check | their own events | unchanged: they record the new values, none of them secret |

**Decision RV11-1: before and after, not new values only.** SEC-805 said settings recorded the new values only and asked for the old value where it helps an investigation. One row that says "the idle time went from 30 to 0 minutes" answers the question an investigator asks without finding the row before, which may have been pruned. Only fields that changed are written, so a row stays small. SEC-805 is now built.

**Decision RV11-2: deny by default.** `settings.Changes` writes values only for the fields a list names as safe; any other changed field is `{"redacted": true}`. The lists sit in `internal/settings/changes.go` for the sections and at each caller of `Write`. `TestEveryFieldOfEverySectionHasAnAuditDecision` fails for a new section field until it is listed as safe or as redacted on purpose.

**Which fields are redacted.** Searched for every secret the product holds: the SMTP password, the identity provider's client secret, the collaboration, metrics and PDF tokens and the database addresses live in the environment (`internal/config`, which already hides them in its report); webhook secrets are sealed in `webhook_endpoints`; API, SCIM and recovery tokens live hashed in their own tables. None of them passes through the settings table, so no settings field holds a secret today. Redacted on purpose is one field: the organisation name of the look, which the first setup may fill with the name of a person. Free texts an administrator writes for every visitor (instance name, welcome text, banner) and the reasons for a longer or shorter retention are recorded: they are public or written as a justification, and an investigation needs them.

**Decision RV11-3: bounded values.** A value longer than 200 characters is cut and marked `truncated`; a list or object whose JSON is longer is kept as cut text. A string that is an address with a user name or password is recorded without them, also for an address stored before this wave. The largest section, the look, has ten fields, so a row stays under about 5 KB.

**The audit screen** shows the whole event as JSON in its dialog, so `changes` appears without a change to the screen.

## 2. The appearance answer

**Before.** `GET /api/v1/appearance` read the font, the look, the logo, the general section and the features from the database on every call: five queries, plus maintenance mode from its own copy of five seconds. Every open tab polls it, and anyone could call it without a login. No limit applied to it: the per-address limits cover login, the account links and the first setup.

**Now.** `settings.Service.Appearance` keeps the five values per node for 30 seconds, as the health facts are kept. The lock is held while it reads, so a change that drops the copy waits for a read in flight and never leaves an older copy behind. Every write of the settings service on that node drops it: a section, a reset of the look, `Write`, `Update`, the logo, the font. Another node shows a change within 30 seconds. Maintenance keeps its own copy, and a banner past its end date is left out at the moment of the answer.

**Decision RV11-4: a limit for callers without a login only.** 600 calls a minute per address (an IPv6 network counts as one), counted as the login limits count, answered with 429 `rate_limited` and `Retry-After`. With the copy the answer costs no database work; the limit stops a flood of encoding work. Someone logged in is not limited, so a whole office behind one address never loses its look; the login limit of 50 tries in 15 minutes per address is already the tighter limit for such an office.

## 3. Two addresses that could mislead

**Decision RV11-5: a link keeps no title.** A link mark kept a `title` of up to 1,000 characters, shown as a tooltip. A tooltip can say `https://bank.example/login` while the link opens another address. The editor offers no field for it; it came only from Markdown (`[text](address "title")`, on import and typed in the editor) or from a client of the API. Capping it would not help, as a short address is enough to mislead. The document gate now drops it and Markdown import no longer takes it. A document stored before keeps its title in the stored version until it is next saved; the reader still shows the real address in the browser's status bar. Image titles stay: an image opens nothing.

**Decision RV11-6: plain http stays for the terms and help addresses; credentials do not.** Internal help sites and intranets often run without a certificate, the address is chosen by an administrator, and a browser shows it before opening it, so refusing http would push those installations to leave the field empty. A user name or password in the address is refused: the appearance answer hands both addresses to anyone without a login, and `https://bank.example@help.example.com` opens `help.example.com`. A stored address with one keeps working until the section is next saved.

## 4. Mutations

Fifteen new lines under "Spec 090, wave RV11" in `scripts/mutation-check.sh`: unlisted field keeps values, organisation name keeps values, long value kept whole, address keeps its credentials, address may carry credentials, a section change, a reset, a stored value, the general values and the backup schedule record nothing before, the appearance read on every call, a section change and a reset leave the old copy, no limit per address, a saved link keeps its title.

## 5. Load

A change reads its row once more, inside the transaction that already locks it: a few reads a day. The appearance answer drops from five queries per call to five per node per 30 seconds.

## 6. Open

- A document stored with a link title keeps it until it is saved again. A one-off rewrite of stored versions was not done: versions are immutable, and the risk is a tooltip that the browser's status bar contradicts.
- `analytics.settings_changed` and `rule.limit_changed` record new values only; neither holds a secret. They could move to `settings.Changes` when those modules are next touched.
- The copy of the appearance is per node; a change on another node shows within 30 seconds. Dropping it on every node through the outbox event `settings.updated` would need a listener on each node.
