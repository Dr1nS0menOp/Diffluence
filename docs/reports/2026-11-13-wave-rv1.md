# Report: wave RV1, rules for administration, editing sockets and logins (13 November 2026)

## What happened

Wave RV1 builds spec 066 in five parts. No migration was needed. The branch was rebased onto main twice, keeping both sides each time:

- after wave DC1, where nothing conflicted;
- after wave RV2, where the proxy of editing sockets, the changelog and the mutation script conflicted.

## What was built

- **Editing sockets.** `/collab` passes neither the admission gates nor the request metrics. It has caps of its own in `internal/httpapi/collab_sockets.go`: 512 per node and 8 per login, keyed by the id of the session. After wave RV2 (spec 067) the proxy checks the session and the right to edit and passes a ticket. The cap is taken after those checks, so a refused socket holds no place.
- **Acting on a system administrator.**
  - `mayActOn` and `mayActOnGroup` in `internal/identity/users.go` guard name and type, status, reset link, second factor, password stop, end date and anonymising, plus additions to and deletion of a group that holds system administration.
  - Taking anyone out of a group is acting on their account, which also covers the members of such a group.
  - Identity providers act as the system and stay leading.
- **Reset links from an administrator.**
  - `POST /admin/users/{id}/reset-password` now calls `SendResetLink`: mailed, or returned once when mail is off. The console shows "Send a password reset link" and the link once.
  - The service function that set a password for someone else is gone. Two tests that used it as a fixture now set the hash directly.
  - SEC-116 is built.
- **Trusted proxies in Compose.**
  - `compose.yaml` passes `DIFFLUENCE_TRUSTED_PROXIES` on, with the default `127.0.0.0/8,::1/128,172.16.0.0/12`. `.env.example` and the install guide explain it.
  - System health gains `proxy_not_trusted`: every login of the last day came from one private or loopback address, by more than one person.
- **OIDC discovery.** A client of its own with a 10-second timeout through `oidc.ClientContext`, discovery outside the lock, waiters share one attempt, and a failure is remembered for 30 seconds.
- **The restore.**
  - It needs `system_administrator`. Others see its state and a line saying who can start one.
  - Codes count against the per-account limiter under their own key.
  - A wrong code is audited as `auth.second_factor_failed` in a transaction of its own.

## How it was checked

- `make check`, green after two fixes:
  - a staticcheck finding on a test that called the same expression twice on either side of `||`;
  - the formatting of two web files.
- **The mutation check.** The script itself changed, so the run held all 796 mutations. 792 were caught.
  - Two older mutations no longer applied: one aimed at the removed function, one at code that changed shape. Both were moved to where the rule now lives.
  - One new mutation did not compile; it was rewritten.
  - One was missed. It removed a group check that the account check already covers, since a member of a system-administration group holds the permission. The check was removed as redundant, with its mutation.
  - The mutations of the four files touched after that run ran again with two jobs.
- **The e2e.**
  - Run: `0-design`, people (with a new test for the reset link), access, backups and health, and collab with the service.
  - The first run of the five lost its database mid-run when Docker recreated the database container, and was run again.

## Not proven

- The default of `DIFFLUENCE_TRUSTED_PROXIES` on a real Compose installation behind a proxy on the host. The tests prove the health check and the parsing, not Docker's gateway address on every machine.
- The socket caps under real load. Only the counting and the order of admission are tested. No test opens nine real sockets through the proxy to see the ninth refused.
- That an installation keeps working when Docker takes its networks from another range than `172.16.0.0/12`. The health check then says so, and the operator sets the range.
