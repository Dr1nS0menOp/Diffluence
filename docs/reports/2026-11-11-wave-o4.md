# Wave O4: the configuration file and `config check`

Report of 2026-11-11. Spec 056; the fourth wave of spec 048. Lines OPS-099 to OPS-102, and OPS-006.

## What was built

- **A configuration file.** `DIFFLUENCE_CONFIG_FILE` names one YAML file, read with `go.yaml.in/yaml/v3` 3.0.6 (MIT and Apache-2.0, no modules of its own). Keys are the variable names in lower case without `DIFFLUENCE_`, flat or nested (`smtp: {host: ...}` is `smtp_host`). The order is default, file, environment; a variable that is set and not empty wins.
- **Strict reading.** These refuse the start and name the line:
  - an unknown key, with a hint when it starts with `DIFFLUENCE_`;
  - a setting written twice, also once flat and once nested, or in another case;
  - a group written twice;
  - a list or a mapping where one value belongs;
  - more than one YAML document;
  - a value of the wrong kind, which names the line too.

  Values are read as the text written, so `no` is refused by a true/false setting and `012` stays `012`.
- **Secrets.** A `_file` key gives a path, like `*_FILE` in the environment. A secret written in the file itself is refused unless only the owner of the file may read it; the message names the key, never the value. A key and its `_file` both in the file are refused.
- **One validator.** `config.Inspect` is the only reader; `Load` is Inspect without the report. Every setting it asks for is a known key of the file, so a setting added later needs no second list (`TestEverySettingIsAKeyOfTheFile`).
- **`diffluence config check [--offline]`** prints each setting, its value in effect and its source, with a secret as `(set)` and a database address without its password. It exits 1 when a start would be refused and 0 otherwise.
- **Settings used later are tried** (OPS-101): the mail server's name and port, the identity provider's discovery document (status, and that it names the same issuer), and a test file in the publish folder, each within 5 seconds and in parallel, never naming an address. `serve` logs them as warnings in the background, and `config check` and `doctor` print them.
- **Compose** no longer repeats three defaults the application has (`PUBLIC_URL`, `SMTP_PORT`, `SMTP_TLS`), so a file can set them, and shows how to mount a file. An empty variable now lets the file's value through, which is what Compose passes for every unset setting.
- **Docs:** the example `deploy/diffluence.example.yaml` (a test loads it), `install.md` with the order, the strictness and the check, `upgrade.md`, the release checklist, `.env.example`, `docs/dependencies.md`, the changelog and the OPS lines.

## Decided during the wave

- **Empty means unset, also for the file's sake.** It always meant the default; letting the file through keeps every installation's behaviour and makes the file usable with Compose.
- **Database addresses count as secrets**, because they hold the password; the report shows them through `url.Redacted`, and not at all when the password is in the query.
- **Probes print no address and no error text of the network library**, which can name hosts, so `doctor` keeps its promise of no addresses.
- **A probe warning does not fail `config check`**: the other system may be down for its own reasons. The check fails only on what a start would refuse.
- **Nested keys join with `_`**, so the file needs no second list of names, and `smtp_host` and `smtp: {host}` are the same setting.

## Not proven

- A secret in a file mode check on Windows hosts: the server runs on Linux, where it is tested.
- OPS-101 on System health: a start only logs the warning.
- OPS-102: no setting was removed; reviewing which ones could be fixed is left open.
