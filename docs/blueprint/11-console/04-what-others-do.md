# 11.4: What other self-hosted products do

How to read this chapter: see [01-console-runs-the-installation.md](01-console-runs-the-installation.md).

Five self-hosted products were read in their **public documentation** on 2026-11-14, for how they split work between the web console and the command line or configuration: GitLab (self-managed), Mattermost, Nextcloud, Discourse and Gitea. No code was read, and nothing is taken but the lesson. The pages are listed in [sources.md](sources.md); where a finding rests only on a forum thread or a search summary, it says so.

## 4.1 What each does

| Question | GitLab | Mattermost | Nextcloud | Discourse | Gitea |
|---|---|---|---|---|---|
| Where settings live | Most in the database, changed in the Admin Area or the API; deployment settings in `gitlab.rb`, applied by a reconfigure that restarts services | Each setting has a console path, a key in `config.json` and an environment variable; the variable wins. The configuration can be moved into the database | `config.php` and the command `occ` for the system; many app settings in the admin pages | Site settings in the database, edited in the admin pages; hidden settings only from the Rails console or the container's environment | `app.ini`, written from environment variables at start; a restart applies a change |
| A value set by the platform | A setting fixed in `gitlab.rb` is locked in the Admin Area, which names who manages it | A setting set by an environment variable cannot be changed in the console | `config_is_read_only` stops the web pages from writing the file | Environment values win for settings that allow it (forum answers only) | Not described |
| Backup and restore | Command only (`gitlab-backup`); the backup leaves out the secrets file, which must be kept apart | Command and database tools only | Command only, with maintenance mode on | Both in the admin pages; restore works only after a setting allows it, and logs everyone out | Command only (`gitea dump`); restore by hand |
| Maintenance mode | Admin Area or API; reads and sign-in keep working, writes get 503 | Not found | Command or `config.php` only; it locks out administrators too | A read-only mode in the admin pages; applies to administrators as well | Not found |
| Upgrades and migrations | The Admin Area shows background migrations and can retry a failed one; starting, pausing and finishing them are commands | Command only | A web updater beside the command line, which the docs recommend for larger installations because of web time limits | An upgrade page from a plugin, refused when the base image is too old; some upgrades need a rebuild on the command line (forum) | Command only; migrations run at start |
| Sessions and log level | A person ends their own sessions; ending another's is the Rails console or an API | The console ends one person's sessions; all sessions through the API; the log level in the console | Commands end a person's sessions; the log level is a command or the file | A restore logs everyone out | The log outputs and levels change at run time by a command |
| Dangerous steps | An "admin mode" asks administrators to log in again before they get their rights, for six hours at most | A setting hides some settings from system administrators | The web updater's limits are about time, not security | Restore is off until allowed; hidden settings carry a warning | `doctor` warns to back up first |

## 4.2 What Diffluence takes from it

- **CSL-350** · built · **The platform's value wins, and the console says so.** GitLab locks a setting fixed in its configuration and names who manages it; Mattermost does the same for an environment variable. Diffluence already shows every start-up setting with its source (spec 056); chapter 08 adds which process holds it.
- **CSL-351** · new · **Restore is off until switched on, and a restore is loud.** Discourse keeps restore off until an administrator allows it, and logs everyone out. Diffluence's console restore is an experimental part that starts off (ADR-043) and asks for a code from the worker's log; this study gives every other step that removes history the same tier (CSL-1205).
- **CSL-352** · new · **Ask again before admin rights.** GitLab's admin mode asks for a login before an administrator acts as one. Diffluence's second tier asks for a fresh login per sensitive action, which is narrower; the third adds a second factor and a code no session can make.
- **CSL-353** · new · **Show migrations, keep their control apart.** GitLab shows background migrations in the Admin Area and leaves pausing and finishing them to commands. Diffluence's upgrade page shows every waiting migration (CSL-560); the only control is running waiting contract migrations before the grace ends, third tier.
- **CSL-354** · not · **No upgrade from the browser.** Nextcloud's web updater and Discourse's upgrade page replace the running software. Both depend on a web process that may write its own code or reach the container manager; Nextcloud's own docs prefer the command line for larger installations. Diffluence's server holds neither right, and should not (CSL-1001).
- **CSL-355** · not · **No backup download or upload.** Discourse lets an administrator download and upload backups in the browser. That carries the whole installation through one session; Diffluence refuses it (CSL-1220).
- **CSL-356** · new · **The log level from the console, but for a while.** Mattermost sets the log level in its console, Gitea changes it at run time by a command. Diffluence takes the run-time change, from the console, with an end (CSL-570).
- **CSL-357** · new · **Ending sessions belongs in the console.** Mattermost ends one person's sessions from its console, and Nextcloud warns that disabling an account ends sessions only after minutes. Diffluence already ends them at once from the console (spec 058); it stays.
- **CSL-358** · built · **Secrets apart from the backup.** GitLab's backup leaves out its secrets file, which the operator must keep apart. Diffluence's backup holds `master.key` only encrypted with the backup key, which is kept apart (spec 054).
- **CSL-359** · new · **Maintenance must not lock out the people who end it.** Nextcloud's and Discourse's modes lock out administrators too. Diffluence keeps login and the maintenance route open during maintenance (spec 013, D17); it stays so.
- **CSL-360** · not · **No configuration file written by the web process.** Nextcloud writes `config.php` from its web pages unless told not to, and Mattermost writes the environment's value back into its file when other settings are saved. Diffluence never writes its configuration file (CSL-1004).
- **CSL-361** · new · **A dump command is not a restore.** Gitea has no restore command and leaves the steps to the operator. Diffluence's restore checks the backup, the key and the release before it changes anything, and its restore test proves a backup restores (CSL-510).
- **CSL-362** · new · **Where none of them goes.** In the pages read, none of the five has the console order work that a separate process with other secrets carries out and confirms with a code from its own log. That pattern is Diffluence's own, from spec 070, and chapter 05 makes it general.
