# 09.14: Load budget

How to read this chapter: see [01-document-control.md](01-document-control.md).

Every feature states what it costs (ARC-238), and wave PF taught that cost must be measured on real data, not on generated data. Document control touches the most-used path there is, reading a page, so its budget is strict: a controlled page must read almost as cheaply as an ordinary one.

- **DOC-1300** · built · One row per controlled page, `page_control`, holds the workflow, the workflow version, the current state and its kind, the approved version number and the working version number. It is the only thing the read path adds. *Why:* walking rounds on every read would grow with history. *Proof:* a query-count test (the budgets of ARC-239) that reading a controlled page costs at most one more query than an ordinary page, or none when joined.
- **DOC-1301** · built · The visibility rule of DOC-300 joins `page_control` into the existing visible-pages rule (wave PF's hash per query), so the tree, search, the feed and reports pay one join, not one query per page. *Proof:* EXPLAIN on the real-data dump that the plan stays a hash join; the real-data benchmark of `scripts/stress/real-data.sh` gains controlled pages and checks the feed, the tree and search within their budgets.
- **DOC-1302** · new · Search's second index entry (DOC-520) is only kept for controlled pages that have a working version different from the approved one, so the index grows only by the drafts in progress. *Proof:* a size check on the benchmark data.
- **DOC-1303** · new · Signing costs one SHA-256 over the canonical form of a version, computed when the version is created and stored, so verifying on display is a comparison, not a hash of the whole page. A full verification (DOC-741) recomputes it and is run by the auditor's export and on demand. *Proof:* a benchmark of signing and display.
- **DOC-1304** · new · The due-date job is one periodic task per worker that claims due rounds by an index on the due time, at most 500 per pass, like the other periodic tasks of wave O1. *Proof:* a test with 10,000 due rounds that the job finishes in passes without holding locks long.
- **DOC-1305** · new · Reports (DOC-1030) and the auditor's export (DOC-1020) run on the read path with the 15-second read limit of wave PF for screens, and as background work for exports, so a large export cannot hold the database. *Proof:* a test that a report on the benchmark data finishes within budget, and that an export runs as background work.
- **DOC-1306** · new · Budgets, measured on the real-data dump with 10% of pages controlled (decided, DOC-1423, as a realistic share for a mixed instance): reading a controlled page within 5 ms more than an ordinary page; the tree and the feed within their PF budgets plus 10%; a transition within 20 ms; signing within 50 ms plus the confirmation. *Proof:* the benchmark, run in each wave, and the next stress test on the server.
