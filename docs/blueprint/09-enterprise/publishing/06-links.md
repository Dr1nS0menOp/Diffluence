# 09.P6: Links across the pair

How to read this chapter: see [01-draft-and-published-spaces.md](01-draft-and-published-spaces.md).

A page of the draft space links to other pages of the draft space. Released as they are, those links would lead readers back into the draft space, where they may not go: the link would show as a page they cannot see (PUB-002). So a release **rewrites** links. Diffluence stores a link by page id, with an optional fragment for a heading or anchor, and looks up what it shows for each reader; that makes rewriting exact: one id is replaced by another, and nothing else of the link changes.

## 6.1 What is rewritten

- **PUB-500** · built · A **page link** (`pageLink`) or **page card** (`pageCard`) to a draft page that has a twin is written into the released document with the twin's id. Its fragment (heading or anchor) and its display stay as they are. *Why:* readers' links must lead to readers' pages. *Edge cases:* headings keep their ids when a document is copied, so a fragment that worked in the draft works in the twin, as long as the twin holds the same version. *Proof:* a test of a link with a fragment, released and followed by a reader.
- **PUB-501** · built · A link to the draft page **itself** (a link to a heading on the same page) becomes a link to the twin. *Proof:* a test.
- **PUB-502** · built · **Blocks that name pages or the space** are rewritten the same way: a list of child pages of a named page, a page tree from a named page, an excerpt or include of another page, and any block attribute that holds a draft page id or the draft space's id or key. The set of such attributes is one list in the code, next to `document.LinkedPages`, and a test fails when a block type with a page or space reference is added without being in it. *Why:* a block that still points at the draft space would show readers nothing, or, if a reader is also a writer, would show them draft content inside a published page. *Proof:* a test per block type; the guard test over the block schema.
- **PUB-503** · built · Blocks that **find pages at read time** (by label, by recent changes in "this space", by search) are not rewritten: in the published space they find published pages, because "this space" is read where the page is. A block that names the draft space explicitly is rewritten to the published space (PUB-502). *Proof:* a test of a label list in a twin that lists twins only.
- **PUB-504** · built · **Placeholder links** (to a page nobody started) are released as their text, never as placeholders. *Why:* following a placeholder creates a page, which nobody may do in the published space (PUB-220). *Proof:* a test.

## 6.2 Links whose target is not released

- **PUB-510** · built · A link to a draft page **without a twin** (not released yet, left out, or a kind that is never released) becomes **its own visible text** in the released document, without a link (decided, PUB-1412). A card becomes the target's title at release time as plain text; an include or excerpt becomes a short muted sentence "This part is not available here." *Why:* a reader must not see a link that leads nowhere, nor learn the id of a draft page; and every version in the published space comes from a release. *Edge cases:* a link whose visible text is empty (a bare card) uses the target's title at release time; if even that would show the title of a page left out for confidentiality, the release manager sees it in the preview (PUB-430) and can change the draft. *Proof:* tests per link kind; a test that no draft id appears in a released document.
- **PUB-511** · built · **Comment anchors**, **instruction text** and any mark that belongs to drafting are removed from the released document. Template fields are refused as at publishing today. *Why:* an anchor names a draft comment (PUB-1406). *Proof:* a test that a released document holds no anchor and no instruction.
- **PUB-512** · new · The page pair records which links stayed text because their target had no twin. When such a target is released later, each page that links to it becomes **Changed since release** with "links waiting" (PUB-306), and the release screen offers to release them together. The text is never turned back into a link by a silent version. *Why:* the release manager decides when readers' pages change (PUB-1412). *Proof:* a test that releasing the target marks the linking page and does not change its twin.
- **PUB-513** · new · In a **branch or whole-space run**, every link to a page in the same run resolves to its twin, also when the target comes later in the order, because twins are made before documents are written (PUB-514). *Why:* a run must not leave its own pages with dead links. *Proof:* a test of two pages that link to each other, released in one run.
- **PUB-514** · new · In batched runs (PUB-451), the twins of every page in the run are made first, in one short transaction, as pages of the published space with no version yet; a page with no version is shown to nobody but its creator, as a draft is today. *Why:* links in early batches need ids of pages in later ones. *Edge cases:* a reader who follows a link to such a twin before its batch lands gets "does not exist, or you cannot see it", as for a hidden page, for at most the time of the run; the preview says this can happen. *Proof:* a test that reads a link target between batches.

## 6.3 Links that stay as they are

- **PUB-520** · partly · Links to pages of **other spaces** stay as they are: they are ordinary links in the published space, and each reader sees them as their rights allow. *Why:* they are not part of the pair. *Edge cases:* a link to a page of another pair's draft space stays a link into that draft space, which readers usually cannot open; the preview counts links into other draft spaces and warns, so the writer can link to the other published space instead. *Proof:* a test of the warning.
- **PUB-521** · built · Links to **addresses outside** Diffluence, mail links and file links within the page are not changed (files are mapped by PUB-320). *Proof:* a test.
- **PUB-522** · new · **Links into the draft space from other spaces** are not touched by a release. The draft space's settings list the pages of other spaces that link into it, as far as the person may see them, so writers can point them to the published space. *Why:* those links usually should lead to the published copy, but changing another space's pages is not this feature's right. *Proof:* a test of the list, as the person may see it.
- **PUB-523** · built · An embedded **database view** and a link to a database show "This part is not available here." in the twin (PUB-232). *Proof:* a test.

## 6.4 Titles, renames and fragments

- **PUB-530** · built · What a link shows is looked up for each reader (PUB-002), so a released link shows the **twin's** title, which changes when the target's rename is released, never before. *Why:* a reader never sees a title that exists only in the draft. *Proof:* a test that renaming a draft page changes no reader's link text until its release.
- **PUB-531** · partly · A link with a **fragment** to a heading that exists in the draft target but not in its released version stays a link to the twin, and opens at its top, as a missing anchor does today. The preview lists such links as "heading not released yet". *Proof:* a test.
- **PUB-532** · built · **Excerpts** shown on cards and in search are made from the twin's text, by the existing excerpt path. *Proof:* covered by PUB-530's test with a card.

## 6.5 Mentions, dates and other inline content

- **PUB-533** · built · **Mentions** of people stay as they are; whom a released mention notifies is said in chapter 09 (PUB-812). Dates, status marks, emoji and anchors stay. *Proof:* a test.
- **PUB-534** · built · Rewriting runs on the **normalised** document and the result is normalised again before it is stored, so a released document passes the same gate as any version (`document.Normalize`). *Proof:* a fuzz test over random documents with links, that rewriting and normalising always succeed and never leave a draft id.
